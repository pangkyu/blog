## 제작하게 된 계기

매번 다른 PC에 납품이나 테스트 환경을 설치할 떄마다 환경 세팅부터 프로그램 설치까지 반복되는 부분에서 많은 피로감을 느꼈습니다.

더 큰 문제는 다른 사용자가 프로그램을 설치하기 어렵다는 점이었습니다. PC의 환경마다 다른 설치 순서와 옵션을 알아야 설치할 수 있었기 때문에 설치 가이드 문서를 만들어 둔다해도 다소 복잡한 구조로 되어있고, 패치가 될 때도 반영하는 부분에서 휴먼 에러의 잠재 위험이 존재했습니다.

따라서 설치를 특정 인원에게 의존하지 않고 쉽게 설치할 수 있도록 Inno Setup으로 설치 마법사를 만들게 되었습니다.

## 인스톨러 설계

인스톨러 제작 시 고려해야하는 점은 아래와 같았습니다.

1. GPU/CPU에 의존되는 환경 세팅 구분
2. 폐쇄망에서도 설치할 수 있어야하는 인스톨러
3. 일반 사용자가 설치할 수 있어야하는 설치 과정

GPU/CPU 환경 구분은 GPU 시리즈별로 필요한 설치 단계가 조금씩 달랐기 때문에, 인스톨러를 따로 만들지 않고 하나의 인스톨러 안에서 설치 시점에 드라이버를 체크해 런타임에 분기하는 방식으로 해결했습니다.

많은 인스톨러 제작 프로그램이 있었지만 아래와 같은 특징으로 Inno Setup을 사용하여 인스톨러를 만들고자 했습니다.

1. 무료로 사용할 수 있는 프로그램
2. 사용자에게 익숙한 "다음 -> 다음 -> 설치"형태의 네이티브 설치 마법사
3. 폐쇄망에서도 쓸 수 있게 설치 파일을 전부 exe 파일 안에 묶을 수 있음

### 패키지 분리 전략

최초 설치에는 환경 세팅과 프로그램 모두 다운받는 것이 문제 없지만, 이후 업데이트 시에는 기 설치된 환경 세팅이 포함된 exe를 받는 것은 불필요한 과정이라고 생각이 들었습니다.
따라서 환경 세팅을 포함한 풀 패키징 설치 파일과, 업데이트용 프로그램을 담은 설치 파일로 나눠 무거운 크기의 환경 세팅을 매번 받을 필요가 없도록 분리하였습니다.

- 환경 세팅을 포함한 인스톨러 : CUDA, Openvino, Python과 같은 한번 설치하면 잘 바뀌지 않는 것
- 프로그램 인스톨러 : 자주 바뀌는 대시보드 및 엔진 프로그램 인스톨러

두 인스톨러에 각자 고정된 AppId를 부여하여 윈도우에서 같은 프로그램으로 인식할 수 있게하여 업데이트 및 삭제를 할 수 있게 세팅하였습니다.

## 온라인 배포

인스톨러를 제작하는 김에 [회사 홈페이지](https://www.aipro.ai/download)에서도 다운받을 수 있도록 R2를 활용한 온라인 배포도 함께 진행하였습니다.

온라인 배포인 경우, 업데이트 체킹을 통해 자동/수동 업데이트 기능도 지원하여 사용자가 재설치하는 과정을 최대한 제거하고자 했습니다.

## 트러블 슈팅

### 1. 인스톨러 설치 후 특정 PC에서 프로그램이 실행되지 않는 이슈

i5-7500 / HD 630을 사용하는 미니PC에서 설치된 프로그램이 실행되지 않는 문제가 있었습니다. 사내에 가지고있는 다른 PC에 동일한 버전으로 테스트했을 때는 문제되지 않던 부분이었기 때문에 이벤트 뷰어를 통해 무슨 문제인지 확인을 진행하였습니다.

이벤트 뷰어에서 `opencl-clang64.dll` 모듈이 크래시된 것을 확인하였고, 구형 인텔 그래픽 드라이버 버전이 원인이었다는 것을 알았습니다.
인텔 드라이버는 세대별로 라인이 나뉘어져 있는데, 7~10세대 CPU를 사용하면서 openvino에서 지원되지 않는 드라이버 버전을 사용하면 크래시가 발생하는 문제였습니다.
GPU 컴파일 크래시는 프로세스 단에서 죽어 try/catch로 잡을 수는 없었기 때문에 근본적인 대응이 필요했기 때문에 CPU버전 설치 시 내장 그래픽 버전을 체크하여 openvino에서 지원되지 않는 드라이버인 경우 openvino를 사용하지 않고 CPU로만 VistaPro 모델 연산을 수행하도록 분기하는 로직을 추가하여 이를 해결했습니다.

### 2. 자동 업데이트 시 프로그램이 보이지 않는 이슈

자동 업데이트를 붙이자 버그가 발생하기 시작하였습니다.

- UAC 프롬프트 : 업데이트 도중 권한 확인 창이 뜨면서 무인 업데이트가 멈췄습니다. 노드 서버는 일반 사용자 권한으로 도는데, 인스톨러는 관리자 권한을 요구하여 발생한 문제였습니다.
  - 설치 시 XML로 예약 작업을 등록하면서 `SecurityDescriptor`에 일반 사용자도 작업을 읽고 실행할 수 있게 설정했습니다.
- 세션 0 격리 : UAC는 풀렸지만 이번에는 시스템 권한으로 도는 작업이 화면이 없는 세션 0에서 실행되는 게 문제였습니다. 처음에는 `Win32_ComputerSystem.UserName`으로 사용자를 찾았는데, 원격 환경에 있는 세션을 감지하지 못하여 `Get-Process -Name explorer -IncludeUserName`으로 실제 데스크톱 사용자를 찾도록 변경하였습니다.

## 마무리

인스톨러 도입 후 잘못된 순서나 옵션으로 설치하다 실패하는 경우가 사라졌고, 가이드 문서를 보며 30분 가까이 걸리던 설치가 몇 분 안에 끝나게 되었습니다. 설치 실패나 문의도 거의 들어오지 않게 되었고, 특정 인원에게 설치를 의존하던 상황도 해소되었습니다.

인스톨러를 만들면서 기존에 개발하던 환경이 아닌 다른 부분들에 대해 공부하게 되었습니다. 제품의 완성도를 높이기 위해 잘 접하지 못한 개발 환경도 공부하면서 완성도를 높일 수 있는 계기가 되었다고 생각합니다.
